## E. Remaining Risks and External Verification Requirements

1. **Live Multi-Process PostgreSQL Concurrency & Migration Execution (`I-02-CONC`, `MIG-0010-IDX`) — `BLOCKED` on Isolated Test Database:**
   - Although `SiteVisitRepositoryPostgres.createStandaloneTransactional()` now locks the parent `enquiries` row (`SELECT ... FOR UPDATE`), checks for an existing active slot (`status <> 'CANCELLED'`), and enforces `uq_site_visits_active_enquiry_slot` in `src/db/schema.ts`, `src/db/client.ts`, and `drizzle/0011_pp10c2_site_visit_active_slot_uniqueness_and_index_alignment.sql`, live execution of Migrations `0010` and `0011` and two-process concurrent PostgreSQL verification could not be run in this workspace because no isolated disposable PostgreSQL database is provisioned (`DATABASE_URL` and `TEST_DATABASE_URL` point to `/greathomes-production`).
   - **Required External Action before Production Release:** Provision an isolated disposable Neon branch (`ALLOW_DISPOSABLE_DB_TESTS=1`), apply `drizzle/0010_pp10b_enquiry_idempotency_and_rate_limits.sql` and `drizzle/0011_pp10c2_site_visit_active_slot_uniqueness_and_index_alignment.sql`, and run two independent Node.js processes concurrently against the disposable PostgreSQL instance to confirm row-locking and `uq_site_visits_active_enquiry_slot` enforcement under real PostgreSQL `READ COMMITTED` transactions.

2. **Infrastructure-Level Proxy Ingress Enforcement (`RL-01-ARCH`) — `NOT VERIFIED / BLOCKED` Outside Application Layer:**
   - Application code in `src/lib/requestContext.ts` now refuses to trust `cf-ray`, `x-vercel-id`, or `x-forwarded-for` unless either a cryptographic constant-time origin shared secret (`CLOUDFLARE_ORIGIN_SHARED_SECRET` / `ORIGIN_INGRESS_SHARED_SECRET`) is verified on the request OR explicit operator ingress enforcement flags (`CLOUDFLARE_STRICT_ORIGIN_INGRESS_ENFORCED=true`, `VERCEL_EDGE_INGRESS_ENFORCED=true`, `REVERSE_PROXY_INGRESS_ENFORCED=true`) are set.
   - However, application code cannot prevent an operator from setting `*_INGRESS_ENFORCED=true` while leaving the origin server directly reachable on a public IP without firewall/mTLS restrictions.
   - **Required External Action before Production Release:** Prefer configuring `CLOUDFLARE_ORIGIN_SHARED_SECRET` / `ORIGIN_INGRESS_SHARED_SECRET` injected via Cloudflare Transform Rules or reverse-proxy config, and independently verify at the cloud firewall / load-balancer layer that direct-to-origin HTTP/HTTPS traffic bypassing the trusted edge is dropped.

3. **Git Repository Metadata Unavailable:**
   - `.git` is absent in `/app/applet`; branch and commit SHA must be verified in the external CI/CD pipeline where the Git repository is hosted.
